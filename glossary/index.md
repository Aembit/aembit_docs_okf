* [3LO](3lo.md) - 3-legged OAuth (3LO) is the OAuth 2.0 Authorization Code flow where a user explicitly authorizes an application to access their data on a third-party service, requiring user interaction to complete the authorization.
* [Access Authorization Event](access-authorization-event.md) - A structured record that Aembit Cloud emits when an Edge Component requests access to a Server Workload.
* [Access Condition](access-condition.md) - Access Conditions add dynamic, context-aware constraints to authorization by evaluating circumstances like time, location, or security posture to determine whether to grant access.
* [Access Discovery Event](access-discovery-event.md) - An access.discovery Access Authorization Event that lists the Client Workloads and Server Workloads that Aembit Cloud considered while evaluating an access request.
* [Access Policy](access-policy.md) - Access Policies define, enforce, and audit access between Client and Server Workloads by cryptographically verifying workload identity and contextual factors rather than relying on static secrets.
* [Aembit Client ID](aembit-client-id.md) - A UUID that Aembit generates when you choose Aembit Client ID as a Client Workload's Client Identification method. It identifies that single Client Workload.
* [Aembit Cloud](aembit-cloud.md) - Aembit Cloud serves as both the central control plane and management plane, making authorization decisions, evaluating policies, coordinating credential issuance, and providing administrative interfaces for configuration.
* [Aembit Desktop](aembit-desktop.md) - Aembit Desktop gives a person working on a Windows 11 machine access to enterprise HTTP and HTTPS services without holding static credentials. The person signs in through their organization's Identity Provider, and a local proxy injects Aembit-brokered credentials into traffic from the tools they run.
* [Aembit Edge](aembit-edge.md) - Aembit Edge represents components deployed within your operational environments that enforce Access Policies by intercepting traffic, verifying identities, and injecting credentials just-in-time.
* [Aembit Secrets Operator](aembit-secrets-operator.md) - Aembit Secrets Operator is a Kubernetes operator that authenticates to the Aembit platform and synchronizes credentials into Kubernetes Secrets for applications to consume directly.
* [Aembit Tenant](aembit-tenant.md) - Aembit Tenants serve as isolated, dedicated environments within Aembit that provide complete separation of administrative domains and security configurations.
* [AI Agent](ai-agent.md) - A software workload that authenticates to systems, requests credentials, and accesses resources, either on behalf of a person or on its own. Aembit secures AI agents with the same identity-first model it uses for any workload. User-driven agents such as Claude Desktop also carry a blended identity that ties access to both the user and the agent.
* [AIDR](aidr.md) - CrowdStrike AI Detection and Response (AIDR) is a content inspection service that scans MCP tool listings, tool call inputs, and tool call outputs in real time and returns an allow, block, or transform verdict to Aembit.
* [Attestation Document](attestation-document.md) - An attestation document is a cryptographically signed JSON document containing workload metadata (such as VM name, UUID, and MAC address) that proves a workload's identity. Aembit Cloud verifies the signature to authenticate the workload.
* [Authorization Context](authorization-context.md) - An evaluation scope that Aembit Cloud uses to tie related Access Authorization Events together.
* [Bearer token](bearer-token.md) - An authentication credential passed in HTTP headers where anyone who possesses the token can use it to access the protected resource. No additional proof of identity is required beyond holding the token itself.
* [Blast radius](blast-radius.md) - The scope of damage that can result from a security breach. A smaller blast radius means a compromised credential or component affects fewer systems and less data.
* [Blended Identity](blended-identity.md) - An access model that combines a human user's identity (authenticated through an Identity Provider) with an AI agent's workload identity into a single access decision, enabling policies that evaluate both "who is this user" and "which agent are they using" simultaneously.
* [Client ID Metadata Document](client-id-metadata-document.md) - A JSON document that an MCP client hosts at an HTTPS URL, containing its client_id, client_name, and redirect_uris. When a client presents that URL as its OAuth client_id, the Authorization Server fetches and validates the document, so the client can authenticate without Dynamic Client Registration (DCR).
* [Client Workload](client-workload.md) - Client Workloads represent software applications, scripts, or automated processes that initiate access requests to Server Workloads, operating autonomously without direct user interaction.
* [Client Workload ID](client-workload-id.md) - A phrase that refers to either a Client Workload's resource ID or its Aembit Client ID, depending on the context in which it appears.
* [Client-to-Gateway Policy](client-to-gateway-policy.md) - The Access Policy that validates which MCP client can connect to the MCP Identity Gateway and authenticates users through your Identity Provider. Also called left-side auth; you create one per MCP client and Gateway combination.
* [Content Security](content-security.md) - Content Security Providers govern the MCP tool traffic flowing through Aembit's MCP Identity Gateway. You add a provider to the Content Security component of an Access Policy.
* [Credential brokering](credential-brokering.md) - The process of mediating credential issuance between a requesting workload and a target resource. The broker verifies identity, evaluates policy, and issues short-lived credentials so that workloads never manage static secrets directly.
* [Credential Provider](credential-provider.md) - Credential Providers obtain the specific access credentials—such as API keys, OAuth tokens, or temporary cloud credentials—that Client Workloads need to authenticate to Server Workloads.
* [Denial of wallet](denial-of-wallet.md) - An attack that exploits consumption-based billing models to inflict financial damage through excessive resource usage. Unlike denial-of-service attacks that crash systems, denial of wallet attacks drain budgets.
* [Dynamic Client Registration](dynamic-client-registration.md) - An OAuth mechanism that allows MCP clients to register with the Authorization Server at runtime without pre-configuration, receiving unique credentials for subsequent authorization requests.
* [Edge SDK Client ID](edge-sdk-client-id.md) - A structured identifier that Aembit generates when you configure a Trust Provider, encoding your region, tenant, and Trust Provider. It identifies a Trust Provider rather than an individual Client Workload.
* [Enterprise-Managed Authorization](enterprise-managed-authorization.md) - An MCP authorization flow in which the corporate identity provider decides which users and AI agents can reach an MCP server, and a trusted party exchanges the user's single sign-on identity for an MCP server access token without a per-user consent prompt.
* [Ephemeral credentials](ephemeral-credentials.md) - Short-lived credentials issued on demand that automatically expire after a configured time period. Because they aren't stored persistently, they reduce the risk window if compromised.
* [ES256](es256.md) - An elliptic curve digital signature algorithm (ECDSA with P-256 and SHA-256) used by Aembit for signing access tokens. ES256 provides strong security with compact key sizes.
* [Gateway-to-Server Policy](gateway-to-server-policy.md) - The Access Policy that authorizes the MCP Identity Gateway to access an MCP server on behalf of authenticated users—the Gateway itself is the Client Workload. Also called right-side auth; each MCP server behind the Gateway needs its own.
* [ISMS (Information Security Management System)](isms.md) - A systematic approach to managing sensitive information, ensuring confidentiality, integrity, and availability. ISO 27001 certifies that an organization's ISMS meets international standards for risk management and security controls.
* [ISO/IEC 27001](iso27001.md) - An international standard for information security management. Certification demonstrates that an organization has implemented comprehensive security controls and risk management processes aligned with ISO 27001 Annex A requirements.
* [JWKS](jwks.md) - JSON Web Key Set - A set of cryptographic keys published at a well-known endpoint, used to verify the signatures of JSON Web Tokens (JWTs) issued by an authorization server.
* [JWT-SVID](jwt-svid.md) - A SPIFFE Verifiable Identity Document in JWT format. JWT-SVIDs are cryptographically signed, short-lived tokens that prove workload identity and enable secure authentication without static credentials.
* [L2 Network Segment](l2-network-segment.md) - A Layer 2 (L2) network segment is a portion of a network where devices communicate using MAC addresses at the data link layer. Devices on the same L2 segment can directly reach each other without routing. MAC addresses must be unique within this boundary for the network to be fully functional.
* [Lateral movement](lateral-movement.md) - An attack technique where an adversary moves through a network after initial compromise, using stolen credentials or exploited trust relationships to access additional systems and escalate privileges.
* [LLMjacking](llmjacking.md) - The unauthorized use of stolen LLM API credentials to consume AI services at the victim's expense. Attackers obtain API keys through exposed repositories, compromised environments, or leaked credentials, then resell access or use it directly.
* [MAC Address](mac-address.md) - A Media Access Control (MAC) address is a unique hardware identifier assigned to a network interface card (NIC). In virtualized environments, the hypervisor assigns virtual MAC addresses to VMs, which Network Identity Attestor uses to verify VM identity.
* [Managed GitLab Account Credential Provider](managed-gitlab-account-credential-provider.md) - An Aembit component that generates and manages Personal Access Tokens for GitLab on behalf of workloads.
* [Match Rule](match-rule.md) - Match Rules are the conditions a Trust Provider evaluates against a workload's attested identity claims, determining which workloads that Trust Provider accepts.
* [MCP App](mcp-app.md) - A UI application that renders inside an MCP host such as Claude Desktop. MCP Apps combine a tool (which declares a UI resource via _meta.ui.resourceUri) with an HTML resource that the host renders in a sandboxed iframe. Defined as an extension to the core MCP specification.
* [MCP Authorization Server](mcp-authorization-server.md) - The Aembit component that provides OAuth 2.1 authorization for Model Context Protocol (MCP) servers, enabling secure access control for AI agents and MCP clients.
* [MCP Authorization Tracing](mcp-authorization-tracing.md) - A live view in the Aembit Tenant that surfaces each inbound authorization request as MCP Identity Gateway receives it, including the redirect URI, resource, matched Client Workload, and Access Policy outcome.
* [MCP Client](mcp-client.md) - An application (such as Claude Desktop, Claude Code, or Gemini CLI) that connects to MCP servers to access tools and resources on behalf of users.
* [MCP Identity Gateway](mcp-identity-gateway.md) - A component that brokers MCP traffic between MCP clients and target MCP servers, validating authorization and presenting Aembit-managed credentials on each request.
* [MCP Resource](mcp-resource.md) - Data that an MCP server exposes for context, such as files, database schemas, or documentation. Unlike tools, which are model-controlled, resources are application-controlled — the client or user decides when to retrieve them, not the model.
* [MCP Server](mcp-server.md) - A server that implements the Model Context Protocol to provide tools, resources, or data to AI agents and MCP clients.
* [MITRE ATT&CK](mitre-attck.md) - MITRE ATT&CK is a globally recognized knowledge base of adversary tactics and techniques based on real-world observations. It provides a common framework for understanding attack patterns and developing defensive strategies.
* [Model Context Protocol](model-context-protocol.md) - A standard protocol for AI agent and server interactions that defines how AI assistants communicate with external tools and data sources.
* [mTLS](mtls.md) - Mutual Transport Layer Security. A TLS handshake in which both the client and server present certificates and validate each other's identity before any application traffic flows. mTLS is commonly used for workload-to-workload authentication where both parties must prove identity at the transport layer.
* [Network Identity Attestation](network-identity-attestation.md) - Network Identity Attestation (NIA) is an Aembit feature that provides cryptographically verifiable identity for workloads in virtualized environments by issuing signed attestation documents based on VM metadata from the hypervisor.
* [Network Identity Attestor](network-identity-attestor.md) - Network Identity Attestor is an Aembit Edge component deployed in VMware vSphere environments that verifies VM identity through the vCenter API and issues signed attestation documents for workload authentication.
* [OAuth 2.1](oauth-2-1.md) - An updated consolidation of the OAuth 2.0 specification that mandates PKCE for all clients, removes the implicit grant and resource owner password grant, and requires stricter security defaults.
* [OpenID Connect (OIDC)](oidc.md) - An identity layer built on top of OAuth 2.0 that lets applications verify the identity of a user or workload and obtain basic profile information using JSON Web Tokens (JWTs).
* [Personal Access Token (PAT)](personal-access-token.md) - A long-lived authentication token used as an alternative to passwords for API access. PATs are commonly used with services like GitLab, GitHub, and Jira, and are a frequent target for credential theft.
* [PKCE (Proof Key for Code Exchange)](pkce.md) - An OAuth 2.0 extension that prevents authorization code interception attacks. The client creates a cryptographic challenge during the authorization request and proves possession of the original secret when exchanging the code for a token.
* [PKCS](pkcs.md) - Public Key Cryptography Standards (PKCS) are a family of standards for cryptographic operations. PKCS#8 defines a format for private keys, while PKCS#1 specifically defines RSA key formats. Network Identity Attestor requires PKCS#8 format for signing keys.
* [Process Hash Attestation](process-hash-attestation.md) - Process Hash Attestation is an Aembit feature that calculates the SHA-256 hash of a workload's executable binary at runtime and embeds it in token claims, enabling zero-trust verification that only approved binaries can access protected resources.
* [Protected Resource Metadata](protected-resource-metadata.md) - OAuth metadata that describes a protected resource (such as an MCP server) and lists its associated authorization servers, enabling clients to discover how to authenticate.
* [RBAC (Role-Based Access Control)](rbac.md) - A security model that restricts system access based on user roles. In Aembit, RBAC controls which administrators can perform specific actions like creating policies, viewing audit logs, or managing credentials.
* [Redirect URI](redirect-uri.md) - The callback URL where the Authorization Server redirects users after authentication. For MCP clients, the redirect URI serves as a Client Workload identifier in Aembit Access Policies.
* [Resource Set](resource-set.md) - Resource Sets are organizational containers that group Access Policy components together, enabling you to manage configurations across different environments, regions, or use cases.
* [Server Workload](server-workload.md) - Server Workloads represent target services, APIs, databases, or applications that receive and respond to access requests from Client Workloads.
* [Service mesh](service-mesh.md) - A dedicated infrastructure layer that manages service-to-service communication in a microservices architecture, typically through sidecar proxies. Handles concerns like load balancing, encryption, authentication, and observability.
* [SOC 2 (Service Organization Control 2)](soc2.md) - An auditing standard for service providers that store customer data in the cloud. SOC 2 Type II reports demonstrate the effectiveness of security controls over time across five Trust Service Criteria - Security, Availability, Processing Integrity, Confidentiality, and Privacy.
* [SPIFFE](spiffe.md) - Secure Production Identity Framework For Everyone (SPIFFE) is an open standard for workload identity that provides cryptographically verifiable identities to services without relying on shared secrets.
* [SPIRE](spire.md) - Secure Production Identity Runtime Environment — the reference implementation of the SPIFFE specification. SPIRE issues and manages cryptographic identities for workloads in distributed systems.
* [Stack](stack.md) - A Stack is the Aembit Cloud deployment that hosts a Tenant. Its domain is the hostname suffix in the Tenant's Edge API URLs, such as useast2.aembit.io in https://<tenantId>.ec.useast2.aembit.io.
* [STRIDE](stride.md) - STRIDE is a threat modeling framework developed by Microsoft that categorizes security threats into six types - Spoofing, Tampering, Repudiation, Information Disclosure, Denial of Service, and Elevation of Privilege. It provides a systematic approach to identifying potential security vulnerabilities.
* [SVID](svid.md) - SPIFFE Verifiable Identity Document. A cryptographically verifiable credential that proves a workload's identity within a SPIFFE trust domain. Aembit issues SVIDS with short lifetimes and automatic rotation. SVIDs come in two formats — X.509-SVID (certificate) and JWT-SVID (token).
* [Token Audience](token-audience.md) - The intended recipient of an access token, specified in the aud claim. For MCP servers, the audience is typically the server's public URL and must match exactly between token issuance and validation.
* [Tool annotations](tool-annotations.md) - Metadata in MCP tool discovery responses that categorize tools by behavior, such as read-only or destructive operations. MCP clients use annotations to drive safety decisions — specifically whether to auto-approve a tool call or prompt the user for confirmation.
* [Tool Invocation](tool-invocation.md) - A control that governs which MCP tools an agent can call, independently of which tools it can discover.
* [Tool Visibility](tool-visibility.md) - A control that governs which MCP tools an agent can discover when it requests a tool listing.
* [trust bundle](trust-bundle.md) - A collection of Certificate Authority (CA) certificates that a SPIFFE-aware workload uses to validate X.509-SVIDs and other SPIFFE identities presented during authentication.
* [Trust Provider](trust-provider.md) - Trust Providers validate Client Workload identities through workload attestation, verifying identity claims from the workload's runtime environment rather than relying on pre-shared secrets.
* [TTL (Time to Live)](ttl.md) - The configured duration for which a credential, token, or cached value remains valid before expiring. Shorter TTLs reduce the window of exposure if a credential is compromised.
* [vCenter](vcenter.md) - VMware vCenter Server is a centralized management platform for VMware vSphere environments that provides VM lifecycle management, monitoring, and APIs for querying VM metadata such as UUIDs and MAC addresses.
* [Workload](workload.md) - Any non-human entity (application, service, automation, AI agent, etc.) that needs to access resources.
* [Workload Attestation](workload-attestation.md) - Workload attestation cryptographically verifies a workload's identity using evidence from its runtime environment, such as platform identity documents or tokens, rather than using static credentials.
* [Workload Event](workload-event.md) - A structured audit record that Aembit generates when application-level traffic flows through Agent Proxy or MCP Identity Gateway.
* [Workload IAM](workload-iam.md) - Identity and Access Management for non-human entities (services, applications, automated workloads) rather than human users. Unlike traditional IAM that manages user access, Workload IAM manages machine-to-machine authentication and authorization.
* [Workload Identity](workload-identity.md) - A unique, verifiable identity assigned to a workload by Aembit.
* [X.509-SVID](x.509-svid.md) - A SPIFFE Verifiable Identity Document in X.509 certificate format. X.509-SVIDs are certificates that embed a workload's SPIFFE ID as a URI Subject Alternative Name (SAN) and enable mutual TLS authentication between workloads. Aembit issues SVIDS with short lifetimes and automatic rotation.
* [Zero trust](zero-trust.md) - A security model that requires verification of every access request regardless of network location. No user, workload, or device is implicitly trusted, even inside the network perimeter.
